# 离线综合报告

已有封存答案时，使用 `benchmark.py compare` 生成单题或多题增强视图。该操作不采样、不重新评分，保留原生单批次报告；适合并列查看质量、速度、稳定性与费用。

## 输入与比较口径

`--run-dirs` 接受一个或多个已完成评分封存的批次，`--models` 可按精确 model ID 筛选。输入须无活跃或未核实请求，并通过封存输入、答案、评分映射与原文依据的只读核对。输出为不存在的新目录，不能放在输入内或包含输入；失败时保留诊断，不修改来源。

只比较特定模型、思考档和速度档时，用 `--condition-filter <JSON>` 代替 `--models`。文件为精确条件列表，例如 `[{"model":"gemini-4-neon-xhigh","effort":"xhigh","service_tier":"default"},{"model":"gpt-6.2-sol","effort":"max","service_tier":"default"}]`；Fast 使用 `priority`。它仅筛选离线展示，核验完整来源但不重采样、不改评分；空列表、重复、缺字段和未命中项会报错。筛选记录进入报告 JSON，计划数和样本数均按所选条件计算。

质量统计按题目、细则、执行模式、源码、指令与稳定运行环境指纹分开，来源批次的条件分别保留，不跨题或跨细则计算质量均值、总榜。展示层可将相同 `case_id / rubric_sha256 / scoring_version / execution_mode` 且维度满分一致的评分组并列为一题；每个配置仍保留原统计、样本、批次和环境身份。V1 保留准确性70、可读性30的原尺度，缺失的覆盖与洞察显示未知；不拆分或换算成V2。相同维度名称与权重不能证明不同细则可合并。

同一原始尝试出现在原评分和重评、或多个重评来源时，拒绝合并，要求选择一个主评分版本。来源识别依据原始采样与尝试的身份，不能按答案文字去重；独立样本回答相同仍各自保留。重评的性能与费用来自原采样，不算新增推理成本。

Fast 优先与同一原采样批次、同题同模型同思考档的 Standard 比较。缺少同批对应项时，仅在双方唯一且无歧义时列跨批历史观察，并披露运行时、时间与环境可能不同；多个候选不自动配对或汇总。该比较描述组中位数变化，不是逐次样本配对或因果效应估计。失败、中断、替代尝试与实际有效 n 单列；未报告的远端完成状态和费用保持未知。

## 报告与解释

`compare` 默认同时导出互相链接的完整 `report.html` 与静态 `compact.html`，无需增加采样。完整报告按题目/细则与思考档筛选，同题各环境配置一次展示，Fast 对照使用全部成员评分组，避免漏掉来源环境中的配置；统计不随展示分组重新合并。

全部来源为V3时额外导出无脚本的 `matrix.html`：按题目与配置横向展示最终分／分钟及含错误或遗漏的答案数。默认“仅看本轮”，在每格下方以三列两行显示准确、覆盖、洞察的基础均值及满分；“显示历史对照”用原评分、复核前评分和差值替换维度，保持表格高度。四题等权均分行同步切换，维度按题目等权平均后才舍入；量表不同时不混算。缺失值保留未知，无历史评分时历史选项不可用。原生单选控件与CSS支持离线键盘切换，不依赖JavaScript，旧`compact.html`和`question-overview.html`继续生成并从顶部提供入口。

展开可逐份查看基础分、原则扣分、适用上限、因果去重组和核验点证据；逐份表的历史分／差值列跟随开关，历史评分审计单独折叠标识。维度属于基础分，最终分先对每份答案应用原则层再统计，可能低于维度之和；不能先平均基础分再统一封顶。历史格式按冻结维度与满分显示，原分仅来自同一原始尝试的封存历史。用户明确要求四题均值时，矩阵的等权均值只描述所列题目，不作为跨条件普遍能力排名。

完整报告展示准确性、覆盖、可读性、洞察的原始尺度与样本数。性能包括耗时中位数、范围与样本点、首字等待、TPS、输出量及明确标注口径的 Fast 收益。工程模式另列答案交付与全树耗时、进度/正文首字、根/子/全树用量和输出吞吐、委派发生率及代理数量；正文解码 token 无法归因时显示未知。独立能力验收与正式样本分开，跨题共用 capability_id 的验收不重复计为本地费用。均值、中位数与费用覆盖次数须各自标明；缺失值不当作零。

紧凑表按题目、档位、速度和模型逐行并列：质量为均值及范围，四维表头从本题细则读取满分；耗时为中位数，用量和费用为均值。行首 `n` 为有效／计划样本；指标覆盖完整时不重复标 n，覆盖不足时仅该值加 `[已知数/有效数]`，未知值保持 `—`。工程模式用“答案交付（秒）”“全部任务结束（秒）”以及全树用量，固定材料模式仅用已有完成耗时和单线程用量。CLI 版本仅从封存运行记录读取，缺失时保持未知。完整批次和环境身份保留在来源详情及 `compact-data.json / compact.csv`，不依赖表格显示列推断来源。

价格单独展示，不生成价格加权质量总分。表格统一单列“估算费用（美元）”，金额使用 `$`，不加“/答”；价格图使用同一美元字段，数值展示均值。包含主代理与全部子孙代理；Standard 1×、Fast 2.5×。不添加计费口径切换或并列另一种价格。沿用封存答案和实际响应 token，按各响应自己的模型与速度档计算，不能把根线程的 Fast 倍率套给所有子代理。

订阅比较权重与来源保存在 `assets/subscription-pricing.json`，规则核对日期与整个快照写入报告 `billing_context`。先使用公开 Standard token credits 权重乘订阅速度倍率，再除以 `usd_equivalent.credits_per_usd`，得到美元等值。当前已核验模型为 25 credits 对应 1 美元等值；这是 Standard token 价格权重的归一化，不是 credits 购买汇率。备注说明订阅 Fast 2.5× 的比较估算不代表实际现金扣费、套餐扣减或余额百分比；另购 credits 的 Fast 2× 不用于这列。Codex 没有独立缓存写入费，输出计数已含推理 token，不另收一次；不套用 API 的长上下文费用，Sol 订阅用量的无长上下文附加费规则由官方文档确认。每次维护费率先核对官方价格和速度文档，更新核对日期；未知模型、速度、用量、美元归一化系数或不完整任务树保持完整美元估算未知，已知部分只留作数据审计，不冒充最终价格。

历史 API 美元、credits、各批价格日期和实际网关未知状态继续保留在下载数据，不因订阅展示重写。原生单批报告的 `summary.json` 保持历史统计兼容，订阅新增值另存 `subscription-prices.json` 并进入 CSV；综合报告在样本和条件中保留 `estimated_subscription_credits`，新增 `estimated_subscription_usd` 及主/子/全树的对应字段。默认 `billing_unit` 为 `USD`。Fast 的实际消耗比含输入、缓存和输出量变化，不等于固定计费倍率。质量触顶时说明区分度不足，小样本与跨批条件差异限制结论。

### 正文 TPS 代理估算

需要估算已封存的工程代理最终正文速度时，可为 `compare` 显式增加 `--estimate-answer-tps`。优先保留已有可归属的原生可见 TPS；其他项目以权威根 `turn/completed` 确认的单个最终正文为准，用 `o200k_base` 计算全文 token 数，再除以首末非空正文片段的客户端到达间隔。流文本不完整、与最终正文不一致、时间缺失或间隔不正时保留未知，不用重试残留或响应总用量代替。

这是统一代理分词，不声称与被测模型的 tokenizer 相同；首片段和客户端缓冲影响结果。新增估算字段与原生可见 TPS、根／全树端到端吞吐分列，展示每组实际 n，逐样本列出时间、token 数与未知原因。模型映射、分词版本、词表 SHA256 和算法来源随新报告封存；不改写原批次、历史费用或评分，不新增采样。

默认执行不依赖第三方库。使用估算选项时，以独立 Python 环境安装 `tiktoken==0.14.0`，将 `TIKTOKEN_CACHE_DIR` 指向该环境的独立词表缓存，先用同一 Python 执行 `import tiktoken; tiktoken.get_encoding('o200k_base')` 预加载公开词表。比较时仅使用预先缓存且 SHA256 为 `446a9538cb6c348e3516120d7c08b09f57c36495e2acfffe59a5bf8b0cfb1a2d` 的词表，不联网下载；正文始终在本地分词。依赖或词表缺失时明确停止，不生成误导性结果。

```text
<isolated-python> benchmark.py compare --run-dirs <sealed-run> --output <new-directory> --estimate-answer-tps
```

可传入 `--assessment <file>`，内容为：

```json
{"conclusion": "基于这些批次的结论及适用条件", "evidence": ["具体题目、指标与事实错误的依据"], "limitations": ["单题、小样本、事后重评或环境差异等实际限制"]}
```

未提供时生成中性说明，不自动写模型推荐。人工分析应先检查事实错误和必答覆盖，再结合可读性、耗时、波动与价格；偏好由当前任务决定，不固化为全局排名。多题报告扩大的是所列题型的证据，不能代替完整工程代理能力测试。

## 导出与验收

正式V3主评分只展示准确性70、覆盖20、洞察10，表达备注不计分；历史包按冻结的维度及权重解释，不能仅凭同号V3识别。当前120份直接对比原采样V2，逐份`previous_scoring_version: 2`、`previous_quality`及`quality_delta=quality-previous_quality`按原始身份和哈希关联；内部试验包仅作派生溯源。紧凑矩阵列V3最终分、V2分、差值、分钟、错误/遗漏答案数及四题等权均值，展开保留分数构成、证据、非计分备注和原始性能详情。说明同一批答案的事后规则修订，分差不代表模型能力变化。

输出包括两种 HTML、条件及逐样本 CSV、Fast 观察 CSV、完整 JSON、紧凑表的 `compact.csv / compact-data.json`、ZIP 和校验清单；两个视图进入同一结果包。报告记录来源封存指纹与文件集合，完成后复核输入文件集合及哈希不变；核对两种视图与源条件的一一对应、CSV/JSON 数值、样本数量、未知字段、ZIP 条目与字节一致性。生成文件仅写目标目录，评测数据与报告不随 skill 进入 Git。

可用离线交互检查验证筛选、图表数据与标签；它不能替代浏览器布局目视检查。交付时说明实际使用的验证方式，以及未完成的可视检查，不把 DOM 模拟称作截图或浏览器验收。
