# 固定证据实验方法

## 选题与证据

目标是日常工程分析，不是模型通识考试。优先读取项目入口、业务路由、主要模块以及近期维护线索，以常见性、代表性、可验证性选择问题。三项都要有工程依据；仅凭函数名“看起来有坑”不够。近期提交、缺陷类型或多处调用可以佐证常见性，但不能把单次异常当高频问题。

新测试形成三道候选并自动选择，不要求用户逐次审批。已有题目通过 history 去重；同主题无更合适材料时允许重用，但说明原因。普通状态转换、配置覆盖、资源路径、失败处理和接口语义都可成为题目；不限定语言、SCM 或 QQSpeed 模块。

问题应包含一个真实场景、必要边界条件及期望输出，例如“解释原因，区分已确认和待验证，给出最小处理与验证建议”。先确认真实源码与日志，再写题；材料要覆盖会改变答案的 helper、调用者、配置、时序和必要旧版对照，不能通过省略关键上下文制造歧义。控制材料规模，不截断导致模型丢失证据。

代理负责验证 gold 的事实正确性：可用静态调用链、既有测试、小型复现或平台原生行为验证，并记录实际结果。避免大型业务构建作为每次默认前置。若问题只能得到主观架构偏好、关键行为无法验证或必须访问外部系统，应缩小范围或更换候选。

## 公平采样

所有组合使用同一封存 prompt、base/developer 指令、相同 provider 和运行时。新临时会话不继承当前聊天；禁检索、工具、插件、MCP 和委派，项目文档读取关闭。可能继承的全局规则仅记录哈希及上下文指纹，不泄露内容；指纹变化停止混合采样。

每轮运行全部组合，保存种子并轮换顺序；串行可减少本地并发争抢。默认五轮，无额外 warmup 推理，不人为清缓存；记录真实缓存用量，再给无缓存输入计费对照。客户端回执只能证明请求与可观测设置，不能独立证明自建网关内部路由或后端思考预算。

保留慢样本、失败及重试历史，不挑最快或最高分的样本。复测是独立批次。单次网络错误由运行时重试并最终成功时记录错误事件数量；它不是应该删除的样本。参数不符、意外工具使用、流与最终答案矛盾属于无效样本，原记录仍保留。

## 指标含义

| 指标 | 口径 |
| --- | --- |
| 总耗时 | 发出 turn/start 至收到 turn/completed；包含排队、网络、思考、输出 |
| TTFT | 同一起点至首个非空可见文字 delta；不是首次隐藏推理 |
| 可见输出 TPS | `(outputTokens - reasoningOutputTokens) / (最后 delta 时间 - 首个 delta 时间)` |
| 输出量 | 总 output token（含 reasoning）、reasoning token、可见 token、文字数和 UTF-8 字节数分别报告 |
| 费用 | 使用本次官方价格和实际 usage 估算；另给输入全部按普通价的对照，不代表重新运行的实际费用 |

可见 TPS 受缓冲和首块输出影响，不能叫纯后端解码速度；仅一个非空 delta 或 reasoning 用量缺失时 TPS 不可用。缺失字段不当作零。客户端前后处理、建会话和评分不计入单次推理耗时。

各指标给 n、均值、中位数、样本标准差、最小与最大值。五次不足以支撑稳定尾延迟或显著性结论，不把思考档名称当必然耗时顺序。

## 质量评分与建议

新建测试默认 `scoring_version: 2`：准确性50、任务覆盖20、边界洞察10、可读性20，合计100。该权重用于日常工程分析，不代表客观最优。未声明版本或明确为1的旧 gold 保持准确性70、可读性30；原题复测沿用原版本，未知版本拒绝。

| V2 维度 | 评价边界 |
| --- | --- |
| 准确性50 | 审核答案已陈述的事实、因果和建议；错误、矛盾、无依据断言在此扣分，不因为缺少要点再扣一次。没有可评价实质内容时为0。 |
| 任务覆盖20 | 按预先列出的子问题、机制和验证要求检查明确回应；未回应为0、部分回应为该项一半、完整回应为满分。回应中的错误归准确性评价，不按正确与否再次扣覆盖分。堆关键词不算回应。 |
| 边界洞察10 | 评价题目未直接逐项要求、但能由材料推出的相关约束、误用影响与反向边界。先列允许的洞察和分值锚点；同义重复只计一次，错误或无关扩展不加分。不能强求超出证据或违反题目要求的发散。 |
| 可读性20 | 评价结论组织、自然准确的表述、详略及建议是否易执行；技术正确性和验证覆盖已在其他维度评价，不在此重复扣。 |

将遗漏与错误分开记录，每个问题注明所属评分项和原文；遗漏可没有直接原文，但需解释缺少什么。`critical` 错误指会改变主要结论、导致错误使用接口或误导排障的事实错误；局部不精确用 `minor`。未展开可选洞察只影响该洞察分，不算事实错误。问题标记用于解释评分，不再从总分额外减分。

细则、分值与证据范围先于推理封存；离线重审则先于此次逐份评分封存，并明确事后性质。V2 每个正分项都附答案原文摘录，0分的遗漏项允许空摘录，不能用旧分数直接缩放替代审计。广度只评价答案呈现的分析角度，不能据推理 token 或耗时判断内部思考范围。

匿名标签只隐藏身份，不能消除所有评分偏见。评分阶段只看 packet；同一 AI 评分者按同一细则逐项写依据，完成后封存，再揭示模型与性能。不宣称评分等于人类偏好，也不为制造排名扩大一两分的差异。

匿名包中的题面和标准答案须保持与推理前的封存输入一致，评分映射须与本批次全部有效答案一一对应。匿名化后新增有效答案时，保留旧的未封存包，再用新的匿名编号重建完整评分包；不能只沿用原先子集的分数而宣称全部答案已评分。

建议先检查关键事实错误和证据缺口，再比较质量接近者的可读性、耗时、费用与波动。允许多个组合各有优势，不强制选唯一冠军。说明这只是当前工程的一道题和当前 provider/版本，不能推断完整工程代理、复杂改码或模型总体能力。若希望更强结论，应由用户另行要求增加题型或样本，不能为“验证建议”自行追加付费调用。

离线重审保留原题、原 gold、原评分及性能记录。新报告单独显示评分版本、四维分布、错误/遗漏和新旧分数；同一答案的分数变化来自评价口径，不能解释为模型能力变化。重新匿名不消除已经见过身份的先验印象，应如实披露。旧新标准不混合排名，旧总分仅在新评分封存后用于差异审计。
