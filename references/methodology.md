# 固定证据实验方法

## 选题与证据

目标是日常工程分析，不是模型通识考试。优先读取项目入口、业务路由、主要模块以及近期维护线索，以常见性、代表性、可验证性选择问题。三项都要有工程依据；仅凭函数名“看起来有坑”不够。近期提交、缺陷类型或多处调用可以佐证常见性，但不能把单次异常当高频问题。

新测试形成三道候选并自动选择，不要求用户逐次审批。已有题目通过 history 去重；同主题无更合适材料时允许重用，但说明原因。普通状态转换、配置覆盖、资源路径、失败处理和接口语义都可成为题目；不限定语言、SCM 或 QQSpeed 模块。

问题应包含一个真实场景、必要边界条件及期望输出，例如“解释原因，区分已确认和待验证，给出最小处理与验证建议”。先确认真实源码与日志，再写题；材料要覆盖会改变答案的 helper、调用者、配置、时序和必要旧版对照，不能通过省略关键上下文制造歧义。控制材料规模，不截断导致模型丢失证据。

代理负责验证 gold 的事实正确性：可用静态调用链、既有测试、小型复现或平台原生行为验证，并记录实际结果。避免大型业务构建作为每次默认前置。若问题只能得到主观架构偏好、关键行为无法验证或必须访问外部系统，应缩小范围或更换候选。

## 公平采样

所有组合使用同一封存 prompt、相同 provider、运行时和执行模式，新会话不继承当前聊天。工程模式使用相同冻结源码、原生工具可用性和权限，允许检索、必要验证与原生委派，不强制每题开代理；不按代理数量评分。保留模型原生指令，封存实际指令链、目录与配置指纹，变化时停止混合采样。无关外部知识入口关闭。显式闭卷模式才关闭工具和委派，不能代表完整工程代理能力；两种模式不可混合排名。

每轮运行全部组合，保存种子并轮换顺序；串行可减少本地并发争抢。默认五轮，无额外 warmup 推理，不人为清缓存；记录真实缓存用量，再给无缓存输入计费对照。客户端回执只能证明请求与可观测设置，不能独立证明自建网关内部路由或后端思考预算。

保留慢样本、失败及重试历史，不挑最快或最高分的样本。复测是独立批次。单次网络错误由运行时内部重试并最终成功时记录错误事件数量；它不是应该删除的样本。参数不符、违反本模式权限或流与最终答案矛盾属于无效样本，原记录仍保留。合法工具调用、失败子任务或可选洞察缺失不能仅因此使工程模式样本无效；任务成败与消耗完整性分别呈现。

## 指标含义

| 指标 | 口径 |
| --- | --- |
| 总耗时 | 发出 turn/start 至收到 turn/completed；包含排队、网络、思考、输出 |
| TTFT | 同一起点至首个非空可见文字 delta；不是首次隐藏推理 |
| 可见输出 TPS | `(outputTokens - reasoningOutputTokens) / (最后 delta 时间 - 首个 delta 时间)` |
| 输出量 | 总 output token（含 reasoning）、reasoning token、可见 token、文字数和 UTF-8 字节数分别报告 |
| 费用 | 使用本次官方价格和实际 usage 估算；另给输入全部按普通价的对照，不代表重新运行的实际费用 |

可见 TPS 受缓冲和首块输出影响，不能叫纯后端解码速度；仅一个非空 delta 或 reasoning 用量缺失时 TPS 不可用。缺失字段不当作零。客户端前后处理、建会话和评分不计入单次推理耗时。

上表总耗时与 TPS 为旧单轮闭卷口径。工程模式分列根 final 交付、根 turn 结束与全树工作结束；按逐响应账本计算全树消耗，不能套根线程价格或把子树 token 除以根正文流时间。具体口径见[工程代理执行](agentic.md)。

各指标给 n、均值、中位数、样本标准差、最小与最大值。五次不足以支撑稳定尾延迟或显著性结论，不把思考档名称当必然耗时顺序。

## 质量评分与建议

新建测试默认正式 `scoring_version: 3`：准确性70、任务覆盖20、边界洞察10，合计100；表达退出计分，并应用下述原则处罚。V2为50/20/10/20且不加原则层；未声明版本或明确为1的旧 gold 保持准确性70、可读性30。退役的四维同号试验包及三维试验包只兼容读取，按冻结维度和权重识别，不原地改写、不再新建或采样。原题复测沿用正式版本，未知版本拒绝。

正式V3的`presentation_notes`为非计分数组；每条仅含原文`quote`及具体阅读障碍`note`，没有障碍填空数组。不按篇幅、排版或风格处罚，不将原表达扣分自动转成事实错误或必答遗漏。无法确认已明确回应必答点时依据该点实际覆盖举证，不能仅凭阅读偏好判错。

正式版本归一时，已完成的三维评分原分导入，沿用全部已封存判断、原文依据、问题和核验点，不重新评阅、采样或计算权重。原始四维到三维的内部派生记录保留溯源，不列为报告中的对照版本。使用十进制计算，仅展示时舍入；主对照按同一原始答案关联原采样评分（当前120份为V2），明确事后规则修订，分差不代表模型能力变化。

### 正式 V3 原则处罚

| 实际影响 | 错误：额外扣分／最高分 | 遗漏：额外扣分／最高分 |
| --- | --- | --- |
| 核心结论 core | 25／59 | 15／69 |
| 关键子结论 key | 10／79 | 6／84 |
| 一般实质问题 local | 3／89 | 2／100 |

核心问题推翻主要结论、根因或可采用的处理方案；关键子结论问题影响重要条件、时序、分支或兼容性而整体判断尚可；一般问题为局部实质错误或必答细节遗漏。纯笔误、格式偏好及未提出可选洞察不受原则处罚。旧critical标记不是core的自动映射，必须说明本问题实际如何影响后续判断。

先计算三维基础分，再对独立因果问题累计额外扣分，取全部适用上限中最低值：`quality=max(0,min(raw_quality-principle_penalty,quality_cap))`。同因重复表述共用group_id，只处罚一次；同因同时有错误和下游遗漏时按错误、取该组最高实际影响等级，不再叠加遗漏处罚。基础分唯一归属和显式原则层分别展示，禁止隐藏额外扣分。

gold冻结`principle_policy`和必答`checkpoints`；检查点权重core/key/local为3/2/1，仅用于辅助错漏比例，不参与额外扣分。分母为题目全部固定核验点权重；不是答案句子数。检查点重要性不自动决定一个局部问题的处罚档，实际影响需单独举证。每点填写correct/error/omission、解释与答案原文；错误/遗漏必须有对应issue，遗漏引用明确必答点；扩展错误check_id可为null，但仍受扣分和封顶，不能通过多写无关正确点稀释处罚。

V3 issue沿用kind、severity、criterion、quote、note，并增加`impact_level`、`group_id`、`check_id`、`reference`、`impact`。core/key映射critical，local映射minor。reference说明正确依据，impact说明实际后果。错误归基础准确性，遗漏归基础覆盖；扩展错误不能伪装成可选洞察缺失。完整参数由core中V3_POLICY校验，报告同时输出基础分、原则扣分、上限、最终分和辅助比例。

| V2 维度 | 评价边界 |
| --- | --- |
| 准确性50 | 审核答案已陈述的事实、因果和建议；错误、矛盾、无依据断言在此扣分，不因为缺少要点再扣一次。没有可评价实质内容时为0。 |
| 任务覆盖20 | 按预先列出的子问题、机制和验证要求检查明确回应；未回应为0、部分回应为该项一半、完整回应为满分。回应中的错误归准确性评价，不按正确与否再次扣覆盖分。堆关键词不算回应。 |
| 边界洞察10 | 评价题目未直接要求、由材料支持且改变诊断或修复判断的额外推导。按下文深度锚点评价实际因果链，不按机制名称或关键词给分；错误、无关或无依据扩展不加分。 |
| 可读性20 | 按实际优点与阅读障碍评价结论组织、自然表述、详略及复核成本，没有默认满分。技术正确性和验证覆盖已在其他维度评价，不在此重复扣；篇幅和格式偏好本身不构成扣分。 |

上表为历史V2维度边界；正式V3准确性满分为70、覆盖20、洞察10，可读性整项改为上述非计分备注。事实错误和必答遗漏继续分别归准确性与覆盖。

制订细则时先分清三类内容：题面要求的必答事项；材料支持但非必答的可选推导；材料不足、只能作为待验证假设的扩展。前两类不能因都涉及同一机制而混计。每个事实错误、必答遗漏或表达障碍在基础评分指定唯一归属；同一问题的后果说明不再重复扣基础分。遗漏可没有直接原文，但需解释缺少什么。V2的critical指会改变主结果、导致误用或误导排障的问题，标记不额外减总分；V3再按实际影响区分core/key/local并应用显式原则层。未展开可选洞察不算遗漏，不扣覆盖、可读性或原则分。

洞察先判断是否为独立额外推导，再评价深度。同一因果链的多种表述只计一次；复述源码、必答结论、常规检查建议不构成额外洞察。按题目材料在评分前固定可计推导数量和权重，不强制固定子项数量，也不把候选机制清单当作自动得分表。以下0–5锚点用于校准深度，再按预先固定的规则映射至本题洞察分值：

| 深度 | 判定依据 |
| --- | --- |
| 0 | 没有额外推导，或仅复述、给常规验证建议、无依据扩展。 |
| 1–2 | 正确识别额外条件及其影响，但因果链或工程后果展开不足。 |
| 3 | 条件、因果链和具体诊断或修复影响完整。 |
| 4 | 进一步给出能区分假设的观测或对照，说明预期差异。 |
| 5 | 还有材料支持的反例、失效条件或对照判据，足以支持有边界的修复决策。 |

明确标注且由材料支持的推演可以得分，不要求实际运行代码或 SDK。提出待验证假设时应标明条件；不把未经验证的实际运行结果当事实。洞察为0可以是合理结果，不为补足分数放宽锚点；高分或满分集中时披露题目或细则区分度不足，不为制造排名扣分。

细则、分值与证据范围先于推理封存；离线重审则先于此次逐份评分封存，并明确事后性质。V2 每个正分项都附答案原文摘录，0分的遗漏项允许空摘录，不能用旧分数直接缩放替代审计。广度只评价答案呈现的分析角度，不能据推理 token 或耗时判断内部思考范围。

匿名标签只隐藏身份，不能消除所有评分偏见。评分阶段只看 packet；同一 AI 评分者按同一细则逐项写依据，完成后封存，再揭示模型与性能。不宣称评分等于人类偏好，也不为制造排名扩大一两分的差异。

材料复杂、细则含混或重评争议较大时，可增加校准与独立复核。先用短例区分复述、常规验证、部分推导和完整判别性推导；若抽取匿名答案校准，预先固定种子与按答案哈希排序的取样规则，不按身份、旧分或期望分布选样。只修正规则含混并记录原因，不根据均分或满分率调参；封存规则后完整评分，包括重新评阅校准样本。

第二评审的抽查范围可按风险预先指定，例如正分洞察、关键事实错误及固定随机子集。独立记录后按冻结规则裁决，保留双方判断和依据，不用平均分掩盖分歧。评审数量、抽样数及是否启用这些步骤随任务决定，不能把未执行的独立复核写进报告。可另列排查、验证或交接质量等侧视评价，每项附原文与正式评分归属，只作解释，不再次加总或扣分。

匿名包中的题面和标准答案须保持与推理前的封存输入一致，评分映射须与本批次全部有效答案一一对应。匿名化后新增有效答案时，保留旧的未封存包，再用新的匿名编号重建完整评分包；不能只沿用原先子集的分数而宣称全部答案已评分。

建议先检查关键事实错误和证据缺口，再比较质量接近者的可读性、耗时、费用与波动。允许多个组合各有优势，不强制选唯一冠军。说明这只是当前工程的一道题和当前 provider/版本，不能推断完整工程代理、复杂改码或模型总体能力。若希望更强结论，应由用户另行要求增加题型或样本，不能为“验证建议”自行追加付费调用。

离线重审保留原题、原 gold、原评分及性能记录。新报告按版本显示有效计分维度、错误/遗漏和新旧分数；同一答案的分数变化来自评价口径或判断修订，不能解释为模型能力变化。重新匿名不消除已经见过身份的先验印象，应如实披露。旧新标准不混合排名，旧总分仅在新评分封存后用于差异审计。

中立复核先区分“问题是否成立”与“影响等级”。通读上下文，保留原文条件与范围；接受跨段完整因果及等价表述。错误需有相反的冻结依据和具体工程影响；遗漏必须对应明确必答或缺失后无法完成任务的必要条件。额外诊断、特定词语及某一个推荐测试组合不能自动升级为必答。证据不足或存在合理解释的争议只作非计分备注，不能扣分或封顶。撤销问题时同步重审基础分，旧问题逐一记录去向；全部计分项允许升、降或不变。程序校验只能证明计算和溯源一致，不能证明评分判断本身客观无误。
